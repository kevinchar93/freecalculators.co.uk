## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
mortgage-form.tsx is ~504 lines with every field inline, making review hard. Break each field (or tightly-coupled field group) into its own subcomponent file. Each subcomponent binds to the Zustand store rather than receiving a long prop list, so mortgage-form becomes a readable layout of composed field components.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 Each logical form field / field group lives in its own component file under the mortgage form
- [x] #2 Field subcomponents read and update the store directly instead of taking individual value/setter props
- [x] #3 mortgage-form.tsx is reduced to composition and layout of the field subcomponents
- [x] #4 Conditional fields (deal, tracker, interest-only) still show/hide correctly
<!-- AC:END -->

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. Create resources/js/pages/mortgage-calculator-page/components/form-fields/ directory with a shared field-styles.ts (toggleSelectedClass, inputClass).
2. Extract each field/field-group from mortgage-form.tsx into its own component in form-fields/, each reading/writing useMortgageStore directly (no value/setter props): mortgage-type-field, property-price-field, deposit-field (incl. LTV badge), mortgage-term-field, interest-rate-field, start-date-field, has-deal-checkbox, deal-fields-group (dealType + conditional tracker rate fields + dealTerm + svr, self-gated on hasDeal).
3. Rewrite mortgage-form.tsx to compose these field components plus the submit button; keep onSubmit as a prop since it is a page-level callback, not store state.
4. Update index.tsx to stop prop-drilling field values/setters into MortgageForm (only pass onSubmit).
5. Run lint/typecheck and the existing vitest suite (index.test.tsx) to confirm conditional show/hide behavior (tracker fields, deal fields, interest rate disabled) still works.
<!-- SECTION:PLAN:END -->
