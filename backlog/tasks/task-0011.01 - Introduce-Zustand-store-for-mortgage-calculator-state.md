## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Replace the ~15 useState hooks in the mortgage calculator page with a single Zustand store so all input values and derived flags live in one place. This is the foundation for the form-field and results-panel refactors: subcomponents read/write the store directly instead of threading dozens of props through index.tsx. Zustand is not yet a dependency and must be added.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 Zustand is added to package.json and a store holds all mortgage inputs (property price, deposit + mode, term, rate, dates, deal fields, SVR/base/margin)
- [x] #2 MortgageCalculatorPage no longer declares per-field useState; it reads state and actions from the store
- [x] #3 Deposit amount/percent sync logic (handleDepositModeChange) lives in the store as an action
- [x] #4 Existing behaviour and tests in index.test.tsx still pass
<!-- AC:END -->

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. Add zustand ^5 to package.json dependencies and install (npm install zustand).

2. Create resources/js/pages/mortgage-calculator-page/store.ts:
   - Module-level useMortgageStore = create<MortgageState>(...).
   - State: all 13 inputs seeded from defaults.json (mortgageType, propertyPrice, depositMode, deposit, depositPercent, mortgageTerm, interestRate, startDate, hasDeal, dealType, dealTerm, svr, baseRate, margin).
   - Setters typed as Dispatch<SetStateAction<T>> so MortgageForm's existing functional-update calls (e.g. setPropertyPrice(v => v+10000)) keep working unchanged. Use a small resolve(value, prev) helper to support both value and updater forms.
   - setDepositMode(mode) action holds the deposit sync logic currently in handleDepositModeChange (percent<->amount conversion using depositAmountToPercent / depositPercentToAmount). Typed (mode: DepositMode) => void to match onDepositModeChange prop.
   - reset() action restores initial state from defaults (for test isolation / future use).

3. Refactor index.tsx:
   - Remove all ~15 useState declarations and the handleDepositModeChange function.
   - Read state + actions from useMortgageStore (select the needed slices).
   - Keep derived values computed in-page from store state (depositAmount, loanAmount, loanToValue, isInterestOnly, isTracker, showSingleCard, showAfterDealCard) via the existing pure calc functions.
   - Wire the same prop names to MortgageForm/ResultsPanel: depositMode + onDepositModeChange={setDepositMode}. No changes to mortgage-form.tsx or results-panel.tsx (props interfaces unchanged) — those refactors belong to TASK-0011.04/.02.

4. Verify: run vitest (index.test.tsx), typecheck, lint. Add beforeEach store reset in the test phase if needed for isolation. Confirm ACs.
