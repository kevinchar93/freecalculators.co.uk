## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Some result content is still hard-coded inline or sourced from demo-data.ts rather than passed as props derived from the store. Establish a single view-model boundary so every panel renders only from props, and wire the demo values in through that boundary. This makes it trivial to later swap demo values for real calculations without touching the panels. No real calculation logic is added here; this is the plumbing that Phase B fills in.
<!-- SECTION:DESCRIPTION:END -->

- [x] #2 A single view-model / mapping layer produces the values panels consume, currently fed by demo data
- [x] #3 Swapping the demo source for real values requires changing only the view-model layer, not the panels
- [x] #4 Page renders identically to before with the demo values flowing through props

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. Export the four card prop interfaces (SingleResultCardProps, DuringDealCardProps, AfterDealCardProps, SummaryCardProps) from their component files so the view-model can be typed against exactly what each panel consumes.
2. Rename fields in demo-data.ts so each exported object's keys match its target card's prop names 1:1 (monthly -> monthlyPayment, date -> endDate, schedule -> paymentSchedule), and drop the unused totalPaidLabel field on the two single-card demo objects (never read by SingleResultCard).
3. Create view-model.ts at the page root exporting getResultsViewModel(isInterestOnly: boolean): { single: SingleResultCardProps; during: DuringDealCardProps; after: AfterDealCardProps; summary: SummaryCardProps }. This function owns the demo-data variant selection (the only branching logic that currently lives inline in results-panel.tsx) and is typed against the card prop interfaces so it cannot drift from what panels expect.
4. Rewrite results-panel.tsx to import getResultsViewModel from ../view-model instead of importing demo-data directly, call it once, and keep explicit named-prop assignment to each card (no spreading, per existing project convention) using the now-matching field names.
5. Verify: npx vitest run index.test.tsx, npm run types:check, visual check in dev server (both mortgage types, hasDeal on/off) to confirm output is pixel-identical to before.
<!-- SECTION:PLAN:END -->
