## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
buildAmortisationSchedule currently returns only a flat monthly ScheduleRow[]. Extend it to also produce an annual breakdown (each year's interest/principal summed from that year's monthly rows, balance taken as the balance at the end of the year), and let the payment schedule accordion switch between the two views via a toggle button so users can see either a detailed monthly schedule or a condensed yearly one.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 buildAmortisationSchedule (or a new function built on it) returns both a monthly row list and an annual row list for a given schedule
- [x] #2 Each annual row's interest and principal equal the sum of that year's monthly interest/principal, and its balance equals the balance after the year's final payment
- [x] #3 PaymentScheduleSection renders a toggle button labelled 'See Annual' when monthly rows are shown and 'See Monthly' when annual rows are shown, switching the displayed rows on click
- [x] #4 The toggle button is only rendered inside the open collapsible content, never visible when the accordion is closed
- [x] #5 Single, During-deal, and After-deal cards all pass both monthly and annual rows through to PaymentScheduleSection and the toggle works correctly on each
- [x] #6 Existing vitest suite and typecheck pass with no regressions
<!-- AC:END -->

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. types.ts: add AmortisationSchedule { monthly: ScheduleRow[]; annual: ScheduleRow[] }.
2. calculations.ts: rewrite buildAmortisationSchedule to a single pass that builds monthly rows as today, accumulates yearInterest/yearPrincipal raw totals, and pushes an annual row (period 'Year N', summed interest/principal, balance = balance at that year's last processed month) every 12 months and on the final month if it lands mid-year. Return { monthly, annual }.
3. copy.json: add paymentScheduleSection.columnYear ('Year'), paymentScheduleSection.showAnnualButton ('See Annual'), paymentScheduleSection.showMonthlyButton ('See Monthly').
4. payment-schedule-section.tsx: change prop from rows: ScheduleRow[] to schedule: AmortisationSchedule; add useState<'monthly'|'annual'> view mode; render a toggle button inside CollapsibleContent (above the table) showing the copy for the *other* mode and switching on click; swap the Month/Year column header and body rows based on view mode.
5. single-result-card.tsx, during-deal-card.tsx, after-deal-card.tsx: change paymentSchedule prop type to AmortisationSchedule; pass schedule={paymentSchedule} instead of rows={paymentSchedule} into PaymentScheduleSection.
6. view-model.ts: no signature changes needed since buildAmortisationSchedule's return type change flows through automatically; after-deal's postDealMonths<=0 zero-card needs paymentSchedule: { monthly: [], annual: [] } instead of [].
7. Typecheck + run vitest suite; manually verify in the running app that the toggle switches rows and stays hidden while collapsed.
<!-- SECTION:PLAN:END -->
