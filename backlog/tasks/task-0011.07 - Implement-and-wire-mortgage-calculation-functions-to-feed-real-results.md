## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
Reference: docs/calculators-specs/mortgage-calculator.md defines the authoritative formulas/symbols per card (dealRate, postDealRate, wholeTermRate, loanAmount, monthlyRepayment, monthlyRepaymentInterestOnly, remainingBalanceKPayments, wholeLoanTotalInterest, amortisationSchedule). Existing calculations.ts already implements the core formulas correctly (verified against the spec's algebra) — this task wires them to real inputs, it does not change the math.

Scope decision (confirmed with user): this task wires real calculations into the CURRENT card props only. It does NOT add the principal/interest split bars, deposit-with-% display, payment-count-in-label, or payment %-change subtext that the spec doc's Outputs section also calls for but which no card component currently has props/UI for — those require new props across 4 components + copy.json and are being filed as a follow-up task instead (see AC#1 note below).

Files changed:

1. resources/js/pages/mortgage-calculator-page/store.ts
   - export the existing `MortgageInputs` interface (currently unexported) so view-model.ts can import the same shape instead of re-declaring it.

2. resources/js/pages/mortgage-calculator-page/calculations.ts (pure, no store/React deps — AC#3)
   - + annualPercentToMonthlyRate(annualPercent): number — annualPercent / 100 / 12; replaces inline literals duplicated in demo-data.ts.
   - + resolveDepositAmount(propertyPrice, depositMode, deposit, depositPercent): number — mirrors the derivation currently inlined in deposit-field.tsx (depositMode === 'amount' ? deposit : depositPercentToAmount(...)); single source of truth.
   - + resolveDealRate(dealType, interestRate, baseRate, margin): number — annual %; fixed -> interestRate, tracker -> baseRate + margin (matches spec's `dealRate` symbol and interest-rate-field.tsx's tracker-disables-interestRate behaviour).

3. resources/js/pages/mortgage-calculator-page/components/form-fields/deposit-field.tsx
   - swap the inline depositAmount ternary for resolveDepositAmount(...) so the form and the results engine share one derivation (avoids the two drifting).

4. resources/js/pages/mortgage-calculator-page/view-model.ts
   - getResultsViewModel(isInterestOnly) -> getResultsViewModel(inputs: MortgageInputs): rewritten to take the full store input shape as an explicit argument (AC#3) and compute single/during/after/summary via calculations.ts functions instead of demo-data.ts constants, per spec:
     - single/summary (no deal): rate = interestRate (wholeTermRate), term = mortgageTerm*12 months.
     - during: rate = resolveDealRate(...), n = mortgageTerm*12 (amortisation base), paid over dealTerm*12 months; balanceAtEnd = remainingBalance(...) for repayment, loanAmount unchanged for interest-only.
     - after: only computed/shown when dealTerm < mortgageTerm; rate = svr, P = during's balanceAtEnd, n = (mortgageTerm - dealTerm)*12.
     - summary: totalPaid = during.totalPaid + after.totalPaid (0 if after hidden); totalInterest = totalPaid - loanAmount (repayment) or totalPaid (interest-only).
   - No import from demo-data.ts remains.

5. resources/js/pages/mortgage-calculator-page/components/results-panel.tsx
   - select the full input set from useMortgageStore (propertyPrice, depositMode, deposit, depositPercent, mortgageTerm, interestRate, startDate, dealType, dealTerm, svr, baseRate, margin, mortgageType) and pass as `inputs` into getResultsViewModel(inputs), replacing today's getResultsViewModel(isInterestOnly) call.

6. Delete resources/js/pages/mortgage-calculator-page/demo-data.ts
   - confirmed via grep it's only imported by view-model.ts and not referenced by any test/story, so nothing to preserve as fixtures (AC#4).

Verification:
7. Typecheck (tsc) + run existing vitest suite (index.test.tsx) to confirm no regressions.
8. Manual sanity-check in the running app: repayment vs interest-only, with/without deal, fixed vs tracker deal type, deal-covers-whole-term (after-card hidden) — compare a couple of figures by hand against the spec formulas.
9. Deep calculation-correctness test coverage is TASK-0012's scope, not duplicated here; competitor validation is TASK-0013's scope.

Follow-up (not in this task, to be filed separately): wire principal/interest split display (PaymentBreakdownBar) into Single/During/After/Summary cards, show deposit as "£Y (Y%)", add payment-count to "Total Paid" labels, add %-change to the after-deal payment-shock subtext — per docs/calculators-specs/mortgage-calculator.md Outputs section.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Implemented per plan. Changes:
- store.ts: exported MortgageInputs so view-model.ts can reuse the same shape.
- calculations.ts: added annualPercentToMonthlyRate, resolveDepositAmount, resolveDealRate (pure, no store/React deps).
- deposit-field.tsx: now uses resolveDepositAmount instead of its own inline ternary.
- view-model.ts: rewritten getResultsViewModel(isInterestOnly) -> getResultsViewModel(inputs: MortgageInputs); single/during/after/summary all computed from real inputs via calculations.ts, matching docs/calculators-specs/mortgage-calculator.md's per-card formulas (dealRate, postDealRate, wholeTermRate, remainingBalanceKPayments, wholeLoanTotalInterest via totalPaid-loanAmount). After-deal card guards postDealMonths <= 0 with a zeroed placeholder (not rendered, since ResultsPanel's showAfterDealCard already hides it) to avoid a divide-by-zero in the amortisation formulas.
- results-panel.tsx: now selects the full input set from useMortgageStore and passes it into getResultsViewModel(inputs); dropped the now-unused isInterestOnly prop.
- index.tsx: dropped the isInterestOnly prop it used to pass to ResultsPanel.
- demo-data.ts deleted (only consumer was view-model.ts; not referenced by any test/story).

Verification:
- npx tsc --noEmit: clean.

- eslint on changed files: only new file (view-model.ts) had import/order issues, fixed with --fix; remaining lint warnings in store.ts/results-panel.tsx are pre-existing (confirmed via git stash), not introduced by this change.
